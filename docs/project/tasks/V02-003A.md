## 总控确定的行为合同

1. 每个 paperId 的三个个人字段保存上次成功生成工作簿的基准值 B；当前 Excel 为 E，SQLite 为 D。逐字段比较：E=B 时保留 D；D=B 时接受 E；E=D 时保留共同值；三者不同则显式冲突，保留双方值，不静默选胜者。
2. 使用工作簿隐藏表持久化基线和格式标记，随临时工作簿原子替换一起发布，避免新增 SQLite schema 或借用分类 membership revision。验证基线完整性和 paperId 身份；不能靠文件 mtime 判断哪个字段更新。
3. 任一内容/身份冲突时，整批个人字段导入不作部分提交，不替换原工作簿；用现有 pending/错误/元数据反馈路径给出可定位的 paperId/字段及原因。冲突双方留存于现有两端，提示先核对/备份再处理；不新增复杂的冲突编辑 UI。
4. 无基线的旧工作簿：若三字段均与 DB 一致，可安全建立基线；存在差异则保守 pending 并保留原文件/DB，不推断某方较新。损坏/缺失/重复基线不能退回无条件覆盖。
5. 清空字符串/单元格是显式编辑；无编辑、双方同值、不同字段分别编辑均按逐字段规则处理。使用事务内重读或条件写入防并发 DB 更新被覆盖；保留工作簿占用、身份异常及原子替换失败保护。
6. 导入成功但导出替换失败后重试必须幂等；冲突状态经重启/worker 重试仍不得绕过。现有个人字段外的数据和持久合同保持不变。
