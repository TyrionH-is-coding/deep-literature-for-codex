## 冻结行为

1. cancel 先做既有身份/范围检查，再原子保存本任务取消意图及稳定控制操作 ID。A stop 的 expectedRevision 必须来自真实 read-control，调用前保存请求。之后分别尝试引擎停止与宿主撤回；一方失败不能阻止另一方的安全取消尝试。分别保存真实结果/安全错误或未知，不能把请求中写成已停，也不因外部失败清意图。重复取消重试同一尚未确认操作；旧 stop 的重放不得在更晚的恢复 revision 上重新停止。保留 completed/failed 与 Reader 事实、独立 child 未停止事实。
2. task/list/reopen 对账权威 control，准确区分 request/ack/terminal 和宿主撤回结果。恢复后可安全补发已持久化的同一 stop，绝不自动 resume。老 schema 1 记录兼容读取；旧 cancelRequested 仅是待核实意图，不能默认成 acknowledged。旧引擎缺能力时仍保存意图和宿主结果，并明确后台停止未确认。普通 submit/dispatch/retryKey/resume/attach 和类别工具不得清除有效引擎 stop；不要因一个合法 stop gate 返回就把操作写成成功恢复。
3. 在既有可信 HTTP resume→operate 路径接受显式 `resumeStopped: true` 与安全整数 `expectedRevision`，以该次 idempotencyKey 派生稳定 requestId（不超过 200 字符），通过 I 导出调用。payload/input/expectedRevision 纳入指纹并在副作用前保存。只有当前权威 revision 证明本次 resume 已接受且没有后来 stop，才清对应本地意图；revision conflict、stop 未确认、未知调度、错误 gate 保留意图并可对账。同一请求丢回执后重试必须用原 ID/输入/revision；旧 completed/observed_progress 回执不清后来取消。普通 attach 不得偷偷解除停止；PDF/gate 恢复沿 A 的真实输入合同，无法满足时明确需要输入，不伪造成功。恢复同 parent/source/generation，不创建替代任务。
4. 不允许分类 agent 自动获得解除停止能力。保留 A 最终守卫，并对本地尚未发到 A 的取消意图拦截目标推进调用；真实会话作用域/任务身份决定保护对象，不能靠任意用户参数声明。共享 turn 与其他任务继续正常工作。不要扩大为全局队列冻结、强杀 provider/worker 或新产品功能。
