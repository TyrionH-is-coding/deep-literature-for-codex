## 冻结语义

1. 引擎 parent job 拥有独立持久控制记录（例如 job 下 control.json，contract=reading-control-v1），不改变现有业务JSON/schema版本。至少有 revision、stopRequested、当前请求ID、停止确认及生效边界；保留足以幂等识别旧请求的操作记录。初始revision=0、未停止。损坏/未知控制记录必须保守拒绝推进，不猜作不存在。
2. 新CLI `full-read-pipeline-stop --job-id --request-id --expected-revision` 幂等请求停止；`full-read-pipeline-control --job-id` 读真实控制状态。回复区分 requested/acknowledged/terminal，包含revision、parent与实际业务状态，不把收到请求或未知PID当作停止完成。新command必须接入现有scope许可和paper身份校验，不扩大分类/论文访问。
3. 停止先落盘，再处理调度。已进入阶段可以完成该阶段的原子产物提交与checkpoint；停止意图生效后不得开始下一阶段或新目标worker。launcher/start、直接advance、worker循环、旧resume/attach和派生child创建边界均不能绕过。确认与阶段入口需互斥，不能“已确认”后再启动阶段。轮询/read/inspect/重启/同键start不解除停止。
4. 不杀进程、不撤销已提交资产。目标worker确认停止后用现有用户gate表达（例如 waiting_user / pipeline_stop_requested），父业务阶段仍可恢复；不得把实际completed/failed改成假的canceled。正在旧版worker中、无新控制能力确认时只报告请求中/兼容限制，不能假称旧worker已停。旧无控制记录任务保持原行为。
5. 现有resume增加显式解除选项 `--resume-stopped --request-id --expected-revision`。只有这种新操作可清除停止，校验scope/source/gate与revision后恢复同一parent；普通旧resume/attach返回停止gate，不推进。旧已完成resume请求重放不得解除后来停止，过期revision拒绝且无副作用。request-id与参数冲突拒绝。同一操作丢回执后可对账重试，不额外启动worker。新接口只供后续B接入，不新增可绕过现有权限的代理工具。
6. 已启动的独立xlsx child不连带终止，控制结果明确此限制；到达派生阶段入口前已请求停止则不新建child。已完成Reader/parse/batch的字节和正式指针保持。不得顺便修复004D直接advance异常、重构默认适配器或升级依赖。
