## 每轮最小检查

1. 读 PROJECT、tasks.json 中活动任务/依赖、本文件及活动卡；按需读取相关差异/报告，不重新载入所有历史材料。检查 Git 状态并保留用户修改。
2. 已登记真实 ID 优先用 wait_threads + cursor 紧凑快照；开发完成通知到达即可验收，无需等下一次定时触发。结合固定 worktree 回执/HEAD/报告判断进度。任务仍健康进行时不发催办消息、不复验未固定源码。
3. 查不到列表不等于不存在，queued/reserved 占名额。必要时仅按本次精确派发提示找本地 session_meta，再用官方 read_thread 核验身份；不把 clientThreadId 当真实 ID，不重复创建。确认 interrupted 后向同一任务恢复一次；若缺权限或输入，保留真实阻塞原因，不反复重启。
4. 超过任务检查点或连续两轮相同失败无新证据时，检查真实工具/提交进展，记录下一步与预算；执行时间长本身不等于失败。连续无证据的失败操作停止自动重试，其他独立工作继续。未知进程状态不标为完成。
5. review 后按[分级验证](session-protocol.md)检查当前提交、允许路径、关键证据和来源。必要补验后串行合入，记录集成提交和未解决事项，再解锁依赖；不机械重跑同一代码已通过的全集。
6. 新发现先分发布阻断、当前目标必需修复、后续改进。当前目标内返工优先发回同一任务；超出允许范围由总控先记录影响与取舍，必要时新卡。不能为每个层次或观察自动递增任务卡，也不能悄悄扩大 v0.2。
