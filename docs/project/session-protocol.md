# 总控与任务协作

2026-09-18 起按用户认可的复盘调整。总控持续协调，开发按任务建立新 session；模块是上下文边界。历史任务的验收事实保留，当前有效行为见本协议和[自动循环](auto-loop.md)。

## 任务边界与预算

- 一张卡交付一个可观察、可验收的行为，包含必要实现、相邻调用方接入和测试。仅为不同文件、方法或内部层次不新开任务；独立提交仍须职责清楚。新功能、运行时升级、数据迁移不夹带。
- 派发前固定目标、非目标、允许路径、依赖接口、baseCommit/contextCommit、独立工作树、风险等级及演示/退出条件。workstream/milestone 先收敛成具体目标；通过诊断可直接结束该工作域，无需强制物理拆模块。
- 默认最多两轮修订后由总控复盘范围和根因；首个 90 分钟为工作量检查点，之后若继续则记录下一检查点及预期证据。这是检查点，不是自动停工时限，也不能降低验收要求或把等待时间算成失败。
- 同一问题连续两次检查没有新证据时，暂停该失败操作并重新选择方法；需要用户或外部条件时仅阻塞受影响链。预算耗尽不标记完成，不自动延伸任务编号。
- 新发现记录影响、复现、分类和处理位置：数据损坏/越界/主流程阻断/失实状态为发布阻断；完成本卡目标所必需的接口问题在卡内修复（总控先确认范围）；非阻断改进进入后续待办。分类不明先限定取证，不能凭猜测升级门槛。

## 上下文与执行

新任务只读 PROJECT、固定任务卡、目标模块说明/公共入口及直接相关实现测试；不复制旧聊天、全量报告或历史计划。当前事实更新到原字段，旧结论留在提交/历史证据中。开发只写自己的工作树，总控独占台账。

启动核对 clean/base 与实际目录，保留已有修改。登记真实任务 ID（clientThreadId 不能替代）、开工回执及 source commit。最多两个开发任务；只有文件、接口、实例、端口、构建输出无冲突且依赖已就绪才并行。合入串行。

## 按风险验证

| 等级 | 适用改动 | 所需验证与复核 |
| --- | --- | --- |
| R0 | 文档、计划、元数据说明 | 链接、JSON/事实与差异检查；模块登记或边界变更另跑 modules check；不跑无关产品全集 |
| R1 | 单模块、低风险可逆修复 | impact + 有意义的定向/模块测试；确有影响才加调用方测试；总控差异复核，不强制另开复核任务 |
| R2 | 持久数据、范围权限、并发状态、跨模块协议、恢复/安装 | impact + 相关模块及调用方合同；总控或独立复核者检查关键失败路径；必要真实进程/来源/安装验证 |

固定源码后执行测试，记录命令、退出码、失败/skip 和实际覆盖；源码变化后只重验受影响证据。相同源码/环境的已验证结果可引用。全量回归在主要集成里程碑和最终候选执行；只有广泛影响或未解释失败才提前扩大，不因多一个任务卡重复 Python/产品全集。modules test 会含下游，重复覆盖不相加。合入只补冲突、差异和组合风险检查，不机械重跑开发者所有测试。

产品发布仍须同一最终制品通过对应安装/恢复门槛；真实模型与内容质量单独验证。降低重复检查不豁免数据安全、隔离范围或未知状态的诚实表述。

## 交接与度量

交接报告约一页：目标/用户可见结果、源码与制品身份、接口/格式变化、实际测试索引、遗留问题分类、回退条件。可复现脚本和必要小型证据入 Git；大量原始日志/夹具库放任务 outputs 或可访问制品，索引记录绝对路径、SHA256、产生它的提交/命令。非跟踪证据标注仅本机可用，不能在验收/保留需要结束前删除；影响最终发布复核的证据随候选归档。旧已跟踪材料不批量删除。

状态是 planned → ready → queued/in_progress → review → integrated；review 不等于通过。只在真实验收并集成后记录 integratedAt、用户可见结果、实际返工轮数及残留缺陷；开始时间缺失则记未知，不倒填。按这些已有记录观察开发到集成耗时、返工与回归、问题定位/恢复耗时；不拿任务数和测试总数衡量交付效果。阶段汇报只说明可用结果、剩余发布阻断和下一项结果，不要求用户阅读全部任务编号。
