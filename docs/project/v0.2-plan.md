## 最低交付范围

可靠完成题录入库 → 获取或补入 PDF → 解析与精读 → Reader 阅读 → 保存记录 → 重启后继续，并能停止后续处理、明确恢复同一任务。保持已验证的身份、个人记录、资产和分类隔离保护。

本轮不加入持久单篇 chat/旧会话迁移、Figure 讨论、跨文献综合、雷达、自定义 Excel 字段、任意模板、选区问答、额外主题、多步骤模型分配。开发 session 的任务化不等于产品聊天改造。额外需求进入后续待办，范围变更须说明收益、替换项及验收成本。

保持工作台 rc.6 模块化基础与已审计引擎来源，运行时 DSH rc.7/Node22.22.2/Python3.11.16/schema4 及锁定依赖不顺带升级。旧 dsh reader 和旧 v0.2 仅作取证，保留用户修改，不整包恢复。

## 实施尺度

任务按完整行为划分，不强制按模块/层逐卡拆；结构整理需说明减少哪种耦合，不以全面重写或文件搬家为完成标准。最大两个独立开发任务，合入串行。每卡约一页目标/范围/验收/交接，详见[协作协议](session-protocol.md)。

采用R0/R1/R2风险验证：日常定向、相关调用方集成、里程碑/最终候选全量；同源码已验证的证据可引用，不重复无变化的Python全集。详细日志归档、当前状态精简，旧证据保留。用交付耗时、返工/回归与定位恢复时间观察效果，缺历史数据不补造指标。

本路线不新增功能、不降低已承诺的数据安全与恢复门槛；在既定范围内总控可自动调整实施方法。新的产品取舍、真实使用与最终发布仍遵守用户授权。
