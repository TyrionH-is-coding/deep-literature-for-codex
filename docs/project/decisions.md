# v0.2 决策记录

## D001 — 2026-09-17：以稳定性和维护成本为首要目标

来源：用户明确反馈“功能太多，流程不稳定、难以维护”。

决定：新 v0.2 推荐采用稳定重构范围。旧 v0.2 的功能进入待办，不凭历史已完成状态自动恢复。新增能力需要说明具体收益与验收成本。

## D002 — 2026-09-17：一个总控，按任务建立开发 session

来源：用户提出并指定当前 agent 担任总控。

决定：并发写入任务最多 1 个；任务结束归档事实，下一项使用新 session。模块和 session 不永久一一对应。复核较大改动时独立进行。

## D003 — 2026-09-17：从精确 rc.6/rc.5 组合重建

来源：当前 Git、pins 和已核实源码。

决定：工作台从模块化 `4eef8bf` 开始，业务引擎从 `8e00b334` 开始。旧本地 dsh reader 的未提交修改保留；远端引擎 main、旧 v0.2 完整包和历史输出均不作为当前基线。

已执行：独立检出引擎 `v0.1.0-rc.5` 并确认 HEAD 与 pins.sourceCommit 相等；没有修改业务代码或安装实例。

## D004 — 2026-09-17：结构重构与行为变化分开验收

决定：结构拆分保持 API、数据格式和运行时基线；可复现缺陷另开修复任务。同一任务不同时更换 DSH、认证、数据库格式和阅读流程。

## D005 — 2026-09-17：恢复要覆盖三个状态域

依据：旧升级说明与验收脚本的范围审查。

决定：文献库/资产、DSH 会话、handoff 绑定及任务回执分别验证。只备份 SQLite 或只检查 ZIP 存在不能宣称完整可回退。跨格式迁移另立任务。

## D006 — V02-001 启动确认

来源：用户先要求确认首个任务范围，随后明确回复“启动”。

决定：仅执行隔离验收与问题定位；允许补充验收脚本、测试样例和报告。所有产品代码修复另立任务，包括模块化引入的加载或路径回归。本次启动不授权后续开发任务自动开工。

## D007 — V02-001 诊断验收与 V02-002 就绪

依据：交付提交 `86d7833`、候选/rc.6 原始 JSON、夹具实现和总控差异复核。

决定：接受 V02-001 的验收与归因交付，将资料集成到总控分支；产品仍有已知问题，main 和发布状态不变。F1 进入记录冲突范围，F2 进入完整恢复范围。两项不阻断只做源码、接口、构建来源与测试基线审计的 V02-002；该任务设为 ready，尚未启动。002 不负责修复 F1/F2，也不直接开启全面重构。

## 待定事项

后续存储、精读作业、Reader 的范围是候选而非必须全面重构；按基线结果缩减、合并或取消，保留可运行的最小改动。

- v0.2 是否必须新增产品内单篇 chat、Figure 讨论或其他能力：当前推荐不作为首版门槛。
- 引擎内部最终模块名、是否需要额外接口层：待 V02-002 根据代码和构建基线确定。
- 真实模型与论文质量样例、发布平台范围：在对应验收任务中明确，不用合成结果代替。
- 现有分支何时合入 main：待 V02-001 的隔离运行门槛通过后由总控组织集成。
