## F1：旧快照覆盖新记录

实际操作：先在 Excel 写入 `合成个人思考 / 部分理解 / V02 saved note` 并 refresh 入库；保持这个快照不变，然后直接在测试 SQLite 更新为 `SQLite newer thought / 深入 / SQLite newer note`，立即查询确认新值已落库；再调用实际安装 wheel 的 `XlsxSnapshotService.refresh()`。

实际结果：返回 `status=success, rows=1`，三个字段都回到旧 Excel 值，`newer_preserved=false`。直接 SQL 写入仅用于建立精确的新旧冲突，不代表已验证任何特定 UI 编辑入口。

静态对应：固定引擎 `engine/src/scientific_reading/xlsx_snapshot.py` 的 `refresh()` 先调用 `import_user_fields()`；后者在文献身份检查后执行 `UPDATE items SET personal_thoughts=?, understanding_level=?, user_notes=? WHERE paper_id=?`，不比较快照基准或字段修改时间。身份检查能防错文献回写，不能防同文献的旧值覆盖新值。

原始 rc.6 对照结果见下方对照段。建议单独建立记录冲突合同任务，先确定权威来源及冲突提示/合并策略，再改引擎及测试；本任务没有修复。
